# Веб-панель камер

Отдельный сервис для просмотра списка камер, добавления, редактирования
и удаления камер, а также просмотра их событий. Сервис написан на Go, интерфейс — HTML/CSS/JavaScript без внешних
библиотек. Установка Node.js для сборки не требуется.

## Запуск

Заполните корневой `.env` по `.env.sample`, как для `api_gateway`.
`WEB_PORT` задаёт порт веб-панели; по умолчанию используется `8088`.

Если `.env` остался от прежней версии проекта, добавьте недостающие параметры:

```dotenv
POSTGRES_PORT=5432
POSTGRES_DATA_FOLDER=./.local/postgres-refactor
HOST_LOGS_PATH=./.local/logs
LOGS_FILE_PATH=/api_gateway/logs/api.log
WEB_PORT=8088
```

`POSTGRES_DATA_FOLDER` — каталог данных PostgreSQL на компьютере;
`HOST_LOGS_PATH` — каталог логов. Имеющиеся имя базы, пользователя, пароль и
`API_PORT` сохраните. Пароль и сам `.env` в Git не добавляются.
Внутри Docker PostgreSQL всегда использует порт 5432; `POSTGRES_PORT`
управляет только портом на компьютере.
Из корня проекта:

```sh
docker compose up --build -d
```

Откройте `http://localhost:8088` (либо свой `WEB_PORT`). Контейнер `web`
ждёт готовности `api_gateway`. Проверка процесса: `/health`.

## Данные и поведение

Браузер обращается к `/api/...` на том же адресе, где открыт интерфейс.
Go-сервер передаёт запросы в `api_gateway` по внутренней Docker-сети.
У веб-сервиса нет подключения к PostgreSQL, драйвера БД или переменных доступа
к БД. Настройки CORS в `api_gateway` не требуются.

Используемые методы:

- `GET /api/camera/list` и `/api/camera/count` — список, статусы и пагинация;
- `POST /api/camera` — добавление камеры;
- `PUT /api/camera/:id` — изменение полей и включение/отключение камеры;
- `DELETE /api/camera/:id` — удаление после подтверждения;
- `GET /api/event/list` и `/api/event/count` с `camera_id`, `created_from`,
  `created_to` — журнал выбранной камеры;
- `GET /api/object/:id` — название обнаруженного объекта.

Кнопки «Изменить» и «Удалить» относятся к выбранной камере.
Редактирование сохраняет ID и время создания. В API можно передавать только
изменённые поля: пропущенные сохраняются, `false` и пустые строки применяются.
Некорректные IP/порты дают 400, отсутствующая камера — 404.
Если у камеры есть события, удаление отменяется с HTTP 409; история не удаляется.

События отображаются от новых к старым; время — в часовом поясе браузера.
Фильтр времени передаётся в API в формате RFC3339 с UTC.
Статус «Включена» отражает `is_enabled`, а не проверку доступности видеопотока.
Фотографии событий пока не отображаются: в API нет метода получения медиа
по `photo_uuid`.

Настройки контейнера:

| Переменная | Назначение |
|---|---|
| `API_GATEWAY_URL` | Внутренний адрес API; Compose задаёт `http://api_gateway:${API_PORT}` |
| `WEB_ADDRESS` | Адрес Go-сервера внутри контейнера; `:8080` |
| `WEB_PORT` | Внешний порт из корневого `.env`; по умолчанию `8088` |

## Проверка

Из корня проекта при запущенном Docker:

```sh
docker compose -f docker-compose.test.yaml up --abort-on-container-exit --exit-code-from tests
docker compose -f docker-compose.test.yaml down
```

Проверяются API с PostgreSQL/pgvector и веб-прокси с тестовым HTTP-сервером:
параметры фильтрации, тело создания камеры, ответы и ошибки шлюза,
доступность статических файлов.

При установленном Go из `services/web/src` также доступны `go test ./...`
и `go vet ./...`.

## Реальные камеры и живое видео

В форме добавления выберите тип подключения:

- **Веб-камера этого компьютера.** Можно оставить камеру по умолчанию или нажать
  «Найти веб-камеры» и выбрать устройство. Затем сохраните камеру и нажмите
  «Смотреть». Браузер попросит доступ к камере. Микрофон не запрашивается.
- **Сетевая камера.** Укажите RTSP/RTSPS или HTTP(S) адрес видеопотока. IP
  определяется из адреса; логин, пароль и HTTP-порт можно задать в дополнительных
  настройках. Адрес без схемы считается RTSP. Например,
  `rtsp://192.168.1.10:554/live` или `http://192.168.1.10:8080/video`.

Веб-камера принадлежит устройству, на котором открыт браузер, а не Docker-серверу.
В БД хранится маркер `webcam://local`, а выбор конкретного устройства — локально
в браузере. Её видео показывается локально и не отправляется на сервер.
Для доступа нужны localhost или HTTPS и разрешение браузера. Подойдут актуальные
Chrome/Edge. На обычном HTTP-адресе в локальной сети браузер может запретить камеру.

Для сетевого видео веб-сервис читает настройки камеры через API, запускает
FFmpeg и отдаёт браузеру MJPEG по `/live/:id`. Чужой `src` из query-параметров
не используется. Параметры запуска передаются без shell, поддерживаются только
сетевые протоколы. FFmpeg уже включён в Docker-образ `web`.
Адрес должен вести на поток, а не на страницу входа в веб-интерфейс камеры.
Docker должен иметь сетевой доступ к камере; `localhost` внутри Docker означает
сам контейнер. В Docker адреса источников `localhost` и loopback автоматически переводятся
в `host.docker.internal` через `CAMERA_LOCAL_HOST`; остальные камеры не меняются.

Просмотр запускается и останавливается кнопками. При смене камеры, открытии
редактирования, уходе со страницы или скрытии вкладки просмотр прекращается.
Обработка потоков ограничена четырьмя одновременными сетевыми просмотрами;
предпросмотр — до 10 кадров/с и размера 960×540, без звука и записи.
Логин и пароль сетевой камеры входят в `stream_url` в БД, но не в адрес
`/live/:id` в браузере и не в сообщения FFmpeg.

Это этап подключения и просмотра. Распознавание и создание событий по видео
ещё не реализованы. ONVIF-поиск и облачные камеры с закрытым протоколом не входят
в этот способ подключения.

Docker-проверка также запускает FFmpeg на настоящем синтетическом видео,
проверяет декодирование кадров MJPEG и JavaScript-разбор адресов/учётных данных.
При запуске локальных Go-тестов без FFmpeg медиатест пропускается; в Docker
его выполнение обязательно (`FFMPEG_TESTS=1`).

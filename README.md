# Курсовая Костян

## Веб-панель камер

В `services/web` находится отдельный веб-сервис: список, добавление,
редактирование и удаление камер, журнал событий с фильтром времени.
Он получает данные только через `api_gateway`.

При запуске `docker compose up --build -d` веб-панель доступна по
`http://localhost:8088`. Порт можно изменить через `WEB_PORT` в `.env`.
Подробности настройки и проверки: [services/web/README.md](services/web/README.md).


Сервис хранения данных системы поиска предметов по камерам. Проект содержит PostgreSQL с pgvector и API на Go: аккаунты, обнаруженные люди и предметы, камеры, места, события, видеофрагменты, траектории и историю запросов пользователя.

API предоставляет создание, чтение по ID, полное обновление и удаление записей. Распознавание видео, генерация ответов, авторизация и пользовательский интерфейс относятся к отдельным компонентам системы.

## Требования

Docker Desktop с запущенным Linux Engine и Docker Compose v2. Все компоненты собираются и запускаются в Docker; устанавливать Go и PostgreSQL на компьютер не требуется.

## Запуск

1. Скопировать `.env.sample` в `.env` в корне репозитория.
2. Заполнить настройки:

   | Ключ | Значение |
   |---|---|
   | `POSTGRES_DB` | Имя базы, например `coursework` |
   | `POSTGRES_USER` | Имя пользователя БД, например `coursework` |
   | `POSTGRES_PASSWORD` | Свой непустой пароль |
   | `API_PORT` | Свободный HTTP-порт, например `18080` |

3. В терминале из корня проекта выполнить:

   ```sh
   docker compose up --build -d --wait --wait-timeout 120
   ```

4. Открыть `http://127.0.0.1:18080/readyz`, подставив выбранный порт. Готовый сервис отвечает:

   ```json
   {"service":"api_gateway","status":"ready"}
   ```

Проверка процесса доступна по `/healthz`, контракт API — по `/openapi.json`. Отдельной веб-страницы на `/` нет.

## API

Для каждой сущности доступны четыре операции. Например, для человека:

```http
POST   /person
GET    /person/:id
PUT    /person/:id
DELETE /person/:id
```

Для создания аккаунта:

```http
POST /user
Content-Type: application/json

{"username":"timur","name":"Тимур"}
```

Подробности полей, обновления и ошибок: [docs/api.md](docs/api.md). Сущности и связи базы: [docs/schema.md](docs/schema.md).

## Устройство проекта

```text
Gin handler → controller сущности → service сущности → dbDAO → PostgreSQL
```

Handler разбирает HTTP-запрос. Controller вызывает сервис. Service проверяет правила данных. dbDAO выполняет параметризованные SQL-запросы. Для каждой сущности предусмотрены отдельные handler, controller и service с методами Create, Get, Update и Delete.

```text
docker-compose.yaml                  Контейнеры, зависимости и volume
.env.sample                          Ключи настроек без значений
scripts/init-db.sql                  Инициализация расширения vector
migrations/                          SQL-миграции Goose
services/api_gateway/
  cmd/gateway/                       Запуск приложения и миграций
  internal/models/                   Модели данных
  internal/dto/                      Входные данные API
  internal/handlers/                 HTTP-хендлеры Gin
  internal/controllers/              Контроллеры сущностей
  internal/services/                 Сервисы сущностей
  internal/dao/                      Доступ к PostgreSQL
  internal/httpapi/                  Маршруты и контракт API
docs/                                Документация
```

## Контейнеры и данные

- `db` — PostgreSQL 17 с pgvector; данные сохраняются в именованном Docker volume.
- `migrate` — одноразовая задача применения миграций; успешное завершение с кодом 0 является штатным.
- `api_gateway` — Go-сервис, запускающийся после готовности базы и успешных миграций.
- `tests` — профиль для автоматических проверок.

HTTP-порт доступен на компьютере через `127.0.0.1`; порт базы на хост не публикуется. `.env` не загружается в Git и не включается в образ. Пароль в уже созданной базе не меняется автоматически при редактировании `.env`.

Образ pgvector устанавливает расширение для хранения и сравнения векторов. Получение векторов моделью и векторный поиск через API в проект пока не входят.

## Проверки и управление

```sh
docker compose --profile test run --build --rm tests
docker compose logs -f api_gateway
docker compose logs migrate
docker compose ps -a
docker compose down
```

Для полной проверки запуска, миграций, API и сохранения данных после перезапуска на Windows можно открыть `Verify.cmd`; на Linux/macOS выполнить `sh scripts/verify.sh`. Оба способа используют Docker.

`docker compose down` сохраняет volume. При обновлении кода повторить запуск с `--build`. Схема изменяется новыми миграциями, а не повторным редактированием init-скрипта. Перед обновлением ценных данных нужна резервная копия.

Конфигурация рассчитана на локальную разработку: вход пользователей и разграничение доступа ещё не реализованы.

# API управления данными

Все маршруты обслуживает Gin. Базовый адрес — `http://127.0.0.1:<API_PORT>`. Версионного префикса и пользовательского интерфейса нет.

## Сущности и маршруты

Для каждого корневого пути предусмотрены POST для создания, GET по ключу, PUT для полного обновления и DELETE для удаления:

| Сущность | Создание | Чтение, обновление и удаление |
|---|---|---|
| Пользователь | `/user` | `/user/:id` |
| Обнаруженный человек | `/person` | `/person/:id` |
| Предмет | `/object` | `/object/:id` |
| Тип предмета | `/object_type` | `/object_type/:id` |
| Событие | `/event` | `/event/:id` |
| Тип события | `/event_type` | `/event_type/:id` |
| Место | `/location` | `/location/:id` |
| Камера | `/camera` | `/camera/:id` |
| Видеофрагмент | `/video_segment` | `/video_segment/:id` |
| Траектория | `/trajectory` | `/trajectory/:id` |
| Точка траектории | `/trajectory_point` | `/trajectory_point/:id` |
| История запроса | `/query_history` | `/query_history/:id` |
| Связь запроса с событием | `/query_event` | `/query_event/:query_id/:event_id` |

`id` — положительное целое число. Последняя таблица имеет составной ключ: ID запроса и ID события. PUT такой связи заменяет пару ключей; адрес результата возвращается в заголовке Location. Старый адрес после изменения пары перестаёт существовать.

GET коллекции, PATCH, пагинация и смысловой поиск не реализованы. Неподдерживаемый метод возвращает 405; неизвестный маршрут — 404.

## Обязательные поля создания и PUT

| Путь | Обязательные поля |
|---|---|
| user | username, name |
| person | Нет; `{}` создаёт или сбрасывает незнакомого человека |
| object | object_type_id, name |
| object_type | name |
| event | event_type_id, camera_id, location_id, occurred_at |
| event_type | name |
| location | name, type |
| camera | location_id, name |
| video_segment | camera_id, start_time, end_time, storage_reference |
| trajectory | person_id, start_time |
| trajectory_point | trajectory_id, observed_at, x, y |
| query_history | user_id, text |
| query_event | query_id, event_id |

Полный список полей, их типы и nullable доступны в контракте `GET /openapi.json`. Схема базы и допустимые состояния описаны в [schema.md](schema.md).

## Примеры

Создать место:

```http
POST /location
Content-Type: application/json

{"name":"Переговорная","type":"room","description":"Первый этаж"}
```

Успешный ответ — 201 и `Location: /location/1`:

```json
{
  "data": {
    "id": 1,
    "name": "Переговорная",
    "type": "room",
    "description": "Первый этаж",
    "coordinates": null
  }
}
```

Создать человека, связанного с существующим аккаунтом:

```http
POST /person
Content-Type: application/json

{"user_id":1,"visual_features":{"label":"пример"}}
```

Прочитать, заменить и удалить запись:

```http
GET /person/1
```

```http
PUT /person/1
Content-Type: application/json

{"user_id":1,"visual_features":{"label":"обновлено"}}
```

```http
DELETE /person/1
```

Операции создания и изменения принимают ровно один JSON-объект с `Content-Type: application/json`. Максимальное тело — 1 МиБ. Повторяющиеся ключи, неизвестные поля, неверные типы и попытки записи полей только для чтения отклоняются.

## Семантика PUT

PUT заменяет все изменяемые поля существующей записи. Обязательные поля требуется передать заново; пропущенные необязательные поля сбрасываются к DEFAULT из БД, то есть NULL, пустой строке или начальному статусу в зависимости от столбца.

Например:

```http
PUT /camera/1
Content-Type: application/json

{"location_id":1,"name":"Камера переговорной"}
```

После этого fps, resolution и stream_url станут NULL, а status — offline. Чтобы сохранить прежние значения, их нужно включить в PUT.

PUT `/person/1` с `{}` сбрасывает необязательные связи, признаки и время обнаружения. `null` допустим только для nullable-полей. ID, created_at и вычисляемая duration_seconds неизменяемы. Внутренний password_hash не принимается и не возвращается обычным CRUD.

Все изменения одной записи атомарны. Если новая комбинация значений нарушает ограничение PostgreSQL, запись сохраняет прежние значения. При отсутствии записи PUT возвращает 404 и не создаёт её автоматически.

## Формат ответов и ошибок

- POST: 201, `{"data":{...}}`, заголовок Location.
- GET и PUT: 200, `{"data":{...}}`.
- DELETE: 204, без тела. Повторное удаление — 404.

Пример ошибки:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Проверьте поля запроса",
    "fields": {"name":"обязательное поле"}
  }
}
```

| HTTP | Значение |
|---|---|
| 400 | Некорректный JSON, повторяющиеся ключи или неверный ID |
| 404 | Запись или маршрут не найдены |
| 405 | Метод не поддерживается |
| 409 | Дубликат уникального значения или конфликт связей |
| 413 | Тело запроса больше 1 МиБ |
| 415 | Неподдерживаемый Content-Type |
| 422 | Неизвестные/неверные поля, отсутствие обязательных значений, нарушение ограничений БД |
| 500 | Внутренняя ошибка без SQL и данных соединения в ответе |
| 503 | Недоступность соединения или отмена запроса |
| 504 | Таймаут операции |

Связанные записи не удаляются автоматически. Например, камеру с событиями или человека с траекториями удалить нельзя: будет 409, данные останутся в БД. Перед изменением места камеры также нужно разрешить ссылки уже записанных событий.

Время передаётся в RFC3339 с часовым поясом: `2026-11-23T15:00:00+05:00` либо `2026-11-23T10:00:00Z`. coordinates и visual_features — JSON-объект или NULL. Числовые ID передаются JSON-числом, не строкой.

## Проверки и ограничения

`Verify.cmd` и `scripts/verify.sh` выполняют контейнерные тесты: миграции, цепочку Gin → controller → service → dbDAO → PostgreSQL, все четыре операции каждой сущности, PUT-сброс полей, конфликты связей и сохранение данных после перезапуска.

Авторизация, загрузка и обработка видео, подключение к stream_url и работа с файлами по storage_reference не выполняются. Текущий API предназначен для локального окружения разработки.

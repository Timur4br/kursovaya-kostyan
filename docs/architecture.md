# Архитектура Go-сервиса

## Поток запроса

```text
HTTP/Gin → Handler → Controller → Service → dbDAO → PostgreSQL
```

Например, `PUT /person/1` проходит через `PersonHandler.Update`, `PersonController.Update`, `PersonService.Update` и `DBDAO.UpdatePerson`.

## Ответственность слоёв

| Слой | Обязанности |
|---|---|
| handlers | Контекст Gin, HTTP-метод и статус, ID из пути, строгое декодирование DTO, заголовки и представление ошибок |
| controllers | Вызов сервиса сущности и координация сценария без зависимости от Gin и SQL |
| services | Проверка обязательных полей, типов, диапазонов и ID; вызов интерфейса доступа к данным |
| dao | Параметризованные SQL-запросы, чтение результата в модель, атомарная замена полей PUT |
| dto | Типизированные входные структуры; различие между отсутствующим полем и явным null |
| models | Типизированные записи, возвращаемые приложением |
| resources | Статические правила полей и список разрешённых SQL-колонок; имена таблиц не берутся из запроса |
| app | Сборка зависимостей: DAO, сервисы, контроллеры и HTTP-роутер |

Для каждой из 12 основных сущностей и связи query_event существуют отдельные файлы handler, controller, service и методы dbDAO. Маршруты регистрируются явно в `internal/httpapi/routes.go`; универсального HTTP-обработчика по имени таблицы нет.

На текущем этапе контроллеры делегируют операции соответствующим сервисам. Их интерфейсы позволят расширять сценарии без переноса бизнес-правил в HTTP-хендлеры. Сервисы не зависят от Gin и конкретного SQL-драйвера; DAO реализует их интерфейсы.

Общими остаются технические механизмы: проверка JSON, безопасное отображение ошибок, параметры SQL и проекция разрешённых полей. Правила связей и согласованности дат также закреплены в PostgreSQL и действуют независимо от способа обращения к API.

## Запуск и миграции

Compose ожидает готовности базы, применяет SQL-миграции Goose и запускает API. `healthz` проверяет процесс; `readyz` — соединение с БД, наличие vector и ожидаемую версию схемы. Обработчики не запускают миграции при запросах.

При завершении процесса HTTP-сервер корректно останавливается. У операций API есть таймаут; тексты SQL-ошибок и параметры подключения в HTTP-ответы не передаются.
